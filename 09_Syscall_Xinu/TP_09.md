## Dasar Teori

System Call (Syscall) adalah mekanisme fundamental yang menyediakan antarmuka antara program aplikasi (user space) dan kernel sistem operasi. Karena aplikasi pengguna tidak memiliki izin langsung untuk mengakses perangkat keras atau mengelola memori inti, aplikasi tersebut harus meminta layanan kepada kernel melalui syscall. Dalam sistem operasi Xinu, syscall digunakan untuk manajemen proses, sinkronisasi (seperti semaphore), dan operasi I/O. <br>

Cara kerja syscall melibatkan instruksi khusus yang memicu perpindahan mode dari user mode ke kernel mode. Saat syscall dipanggil, sistem akan menghentikan sementara eksekusi program pengguna, beralih ke tabel vektor interupsi, dan menjalankan fungsi kernel yang relevan sebelum akhirnya mengembalikan kontrol (dan sering kali hasil data) kepada program pengguna. Mengubah atau menambah syscall dalam kernel seperti Xinu memberikan pemahaman mendalam tentang bagaimana instruksi tingkat rendah dikelola untuk menjaga stabilitas dan keamanan sistem. <br>

## Guided

### Buat Syscall Baru
- Langkah Implementasi: Proses ini melibatkan beberapa tahapan kritis, dimulai dari mendefinisikan prototipe fungsi syscall di file header kernel, menambahkannya ke dalam tabel sistem agar dikenali oleh kompilator, hingga menuliskan logika fungsi di dalam direktori system/. <br>

- Mekanisme: Syscall yang dibuat berfungsi untuk memberikan layanan baru kepada pengguna (dalam hal ini, menjalankan fungsi spesifik yang ditentukan di modul). Setelah kode ditulis, kernel harus dikompilasi ulang menggunakan perintah make agar syscall baru tersebut terdaftar secara permanen dalam sistem biner Xinu. <br>

- Hasil: Berdasarkan hasil running pada screenshot, syscall berhasil dipanggil dari shell Xinu tanpa menyebabkan kernel panic. Ini membuktikan bahwa registrasi fungsi di dalam tabel syscall telah dilakukan dengan benar dan kernel mampu mengeksekusi instruksi tersebut dalam kernel mode. <br>
