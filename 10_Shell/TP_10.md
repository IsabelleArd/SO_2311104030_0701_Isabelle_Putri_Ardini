## Dasar Teori
Shell adalah sebuah program aplikasi yang bertindak sebagai antarmuka berbasis teks (Command Line Interface atau CLI) antara pengguna dengan kernel sistem operasi. Shell berfungsi untuk membaca perintah yang diketikkan oleh pengguna, menguraikannya (parsing), dan mengeksekusi program atau system call yang sesuai. Pada sistem operasi Embedded Xinu, shell diimplementasikan melalui subsistem xsh. Setiap perintah yang ada di dalam shell Xinu sebenarnya direpresentasikan oleh sebuah fungsi C khusus (biasanya diawali dengan prefiks xsh_) yang didaftarkan ke dalam tabel perintah shell.<br>

Untuk memanipulasi atribut dari suatu proses melalui perintah shell, kernel menyediakan system call (syscall). Salah satu atribut penting pada tabel proses (process table) adalah nama proses, yang disimpan dalam array karakter di dalam struktur data procent. Ketika sebuah perintah shell ingin mengubah nama proses, ia harus melewatkan parameter seperti ID Proses (PID), string nama baru, dan panjang karakter ke tingkat kernel melalui syscall seperti chname(). Modifikasi pada shell dan syscall Xinu memerlukan sinkronisasi antara file header konfigurasi (prototypes.h), implementasi fungsi kernel (chname.c), konfigurasi perintah shell (shell.c), dan pembuatan berkas perintah baru (xsh_namecmd.c).<br>

## Guided

### 1. Modifikasi Syscall chname dengan 3 Parameter
Penjelasan:<br>
Pada tugas pertama, kita diminta untuk mengubah struktur dan logika dari syscall chname(). Secara default, chname pada Xinu mungkin hanya memiliki parameter terbatas atau struktur yang mirip dengan chprio. Di sini, kita mengubahnya agar menerima 3 parameter spesifik: pid32 pid (ID proses yang akan diubah), char *newname (pointer ke string nama baru), dan uint32 namelen (panjang karakter nama baru).<br>

Mekanisme Perubahan:<br>
- prototypes.h: Mengubah deklarasi eksternal fungsi menjadi extern pri16 chname (pid32, char *, uint32); agar modul lain mengenali tanda tangan (signature) fungsi yang baru.<br>
- chname.c: Mengubah definisi fungsi di dalam kernel. Di dalam kode ini, kita menambahkan validasi untuk memastikan pid yang dimasukkan berada dalam rentang valid (0 hingga NPROC). Jika valid, kernel akan menyalin string dari newname sebanyak namelen karakter ke dalam field nama pada tabel proses (proctab[pid].prname) menggunakan fungsi manipulasi string yang aman atau perulangan, lalu memastikan karakter terakhir ditutup dengan null-terminator (\0).<br>

Analisis: Modifikasi ini memberikan fleksibilitas bagi kernel untuk mengubah identitas visual atau nama sebuah proses secara dinamis saat sistem sedang berjalan (runtime).<br>

### 2.Pembuatan Perintah Baru namecmd pada Shell
Penjelasan:<br>
Tugas kedua bertujuan untuk membuat sebuah perintah shell baru bernama namecmd. Perintah ini berfungsi sebagai wrapper di user space untuk menguji syscall chname yang telah kita modifikasi sebelumnya.<br>

- Logika Implementasi: Kita membuat file perintah baru (misalnya xsh_namecmd.c) di direktori shell Xinu. Di dalam fungsi tersebut, kita menambahkan instruksi untuk mencetak teks "My new command". Selanjutnya, fungsi ini melakukan pemanggilan konkret terhadap syscall: chname (3, "hello", 5);. Kode ini secara eksplisit memerintahkan kernel untuk mengubah nama proses dengan PID 3 (yang awalnya bernama netin) menjadi nama baru yaitu "hello" dengan panjang 5 karakter.<br>
- Integrasi Shell: Agar perintah namecmd bisa langsung diketikkan di terminal Xinu, kita harus mendaftarkannya ke dalam file konfigurasi shell (seperti tabel cmdtab di file shell.c) lengkap dengan nama perintah dan fungsi eksekusinya.<br>

### 3. Pengujian Hasil (Testing)
Penjelasan:<br>
Tahap ketiga adalah melakukan validasi apakah modifikasi syscall dan penambahan perintah shell baru telah bekerja secara sinkron dan benar.<br>

Prosedur Pengujian:<br>
